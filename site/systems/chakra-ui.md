## Install
```bash
npm install @chakra-ui/react @emotion/react
npx @chakra-ui/cli snippet add      # adds provider, color-mode and other snippets to your repo
```

## Setup
```tsx
import { Provider } from '@/components/ui/provider';   // generated by the CLI
export default function RootLayout({ children }) { return <html suppressHydrationWarning><body><Provider>{children}</Provider></body></html>; }
```

## Theme it to a brand
v3 uses `createSystem(defaultConfig, { theme: { tokens: { colors: { brand: { 500: { value: '#…' } } } }, semanticTokens: {…} } })` and passes it to `ChakraProvider value={system}`. Generate types with `npx @chakra-ui/cli typegen`.

## Agent tips
- MCP server: `npx -y @chakra-ui/react-mcp` (component props, examples, v2→v3 migration).
- `https://chakra-ui.com/llms.txt` has per-component docs. Chakra v3 API differs from v2 — don't use v2 examples.

## Build checklist (any system)
1. **Install & provider:** follow the install section exactly for the detected framework and version.
2. **Brand → tokens:** set primary/neutral colours, radius, font family and density through the system's theme/tokens API, once, at the root. No hard-coded hex values in components.
3. **App shell first:** build navigation, header and page layout from the system's shell/layout components.
4. **Screens from components:** map each screen of the product idea to existing components and patterns (tables, forms, dialogs, empty states). Only write a custom component when nothing fits, and build it from the system's primitives and tokens.
5. **States:** loading, empty, error and success states for every data view, using the system's skeleton/alert/toast components.
6. **Accessibility:** keep the system's semantics (labels, roles, focus management); check keyboard navigation and colour contrast after theming.
7. **Dark mode & responsiveness:** enable the system's colour-scheme support; check at phone and desktop widths.
8. **Verify:** run the app, click through every screen, fix console errors and type errors.
